# CLAUDE.md

Guidance for working in this repository.

## Project overview

A personal developer portfolio website (the `Simplify4Me2.github.io` GitHub Pages site).
It showcases a homepage, a portfolio overview, four project detail pages (Bookmark,
Fylo, Insure, Manage), and a contact page. It is a static single-page app.

## Tech stack

- **React 19** with **TypeScript**
- **Vite 5** (build tool) with `@vitejs/plugin-react-swc`
- **Tailwind CSS 3** for styling (`darkMode: 'selector'`)
- **MUI (`@mui/material`) + Emotion** are available as dependencies
- **react-router-dom 6** using `HashRouter` (required for GitHub Pages — routes are hash-based, e.g. `/#/portfolio`)
- **Storybook 8** for component development
- **PostHog** (`posthog-js`) for analytics
- **Yarn** is the package manager (see `yarn.lock`). Do not introduce `package-lock.json`.

## Commands

```bash
yarn              # install dependencies
yarn dev          # start the Vite dev server (HMR)
yarn build        # type-check (tsc) then build to dist/
yarn lint         # ESLint over ts/tsx — must pass with 0 warnings
yarn preview      # preview the production build locally
yarn storybook    # run Storybook on port 6006
yarn deploy       # build + publish dist/ to the gh-pages branch via gh-pages
```

`yarn build` runs `tsc` first, so a type error will fail the build. Run `yarn lint` and
`yarn build` before considering a change complete.

## Deployment

- Pushes and PRs to `master` trigger `.github/workflows/deploy.yml`, which builds and
  deploys to GitHub Pages.
- `yarn deploy` is the manual path (publishes `dist/` to the `gh-pages` branch).
- `homepage` in `package.json` is `https://simplify4me2.github.io`.

## Project structure

```
src/
  App.tsx              # routes (HashRouter); LayOut wraps pages with Header + Footer
  main.tsx             # entry; wraps App in PostHogProvider + React.StrictMode
  Header.tsx           # site header with responsive desktop/mobile nav
  Footer.tsx           # site footer
  index.css / App.css  # global styles + Tailwind layers + CSS color variables
  components/           # reusable UI components, re-exported via components/index.ts
  pages/                # route-level pages (home, portfolio/*, contact), barrel index.ts
  images/               # per-asset responsive <Image> wrapper components
  hooks/                # custom hooks (e.g. useScrollToTop, useDarkModeState)
  assets/               # images (mobile/tablet/desktop variants) + SVG icons + logo
  fonts/                # IbarraRealNova (serif) and PublicSans (sans) font files
  stories/             # Storybook example stories/assets
public/                 # static files copied as-is (logos, vite.svg)
dist/                   # build output — generated, do not edit by hand
```

## Conventions

- **Barrel exports**: folders like `components/`, `pages/`, `pages/portfolio/`, `images/`,
  and `hooks/` expose their members through an `index.ts`. Add new modules to the
  relevant barrel and import from the folder, not the file.
- **Component exports**: most components use named exports; a few use `default`
  (e.g. `ArticleHeader`). Match the existing export style of the folder's `index.ts`.
- **Styling**: prefer Tailwind utility classes inline, matching the existing responsive
  pattern (`md:`, `lg:` breakpoints). Custom theme colors (`bright-red`, `dark-blue`,
  `slightly-desaturated-cyan`, etc.) and font families (`font-serif`, `font-sans`,
  `font-publicSans`, `font-ibarra`, `font-rubik`) are defined in `tailwind.config.js`,
  backed by CSS variables. Use these tokens rather than raw hex values.
- **Responsive images**: the `Image` component in `src/images/Image.tsx` renders separate
  mobile/tablet/desktop `<img>` elements toggled by Tailwind breakpoints, with
  `loading="lazy"`. Per-asset wrappers in `src/images/` follow this pattern.
- **Routing**: use `react-router-dom` `Link`/`useLocation`. Because the app uses
  `HashRouter`, do not assume server-side path routing.
- **Lazy loading**: page-level routes (`Home`, `Overview`, `Contact`) are loaded via
  `React.lazy` + `Suspense` in `App.tsx`.

## Environment variables

Vite env vars live in `.env` (gitignored — do not commit it). The app reads:

- `VITE_PUBLIC_POSTHOG_KEY`
- `VITE_PUBLIC_POSTHOG_HOST`

All client-exposed variables must be prefixed with `VITE_`. Never commit secrets or the
`.env` file.

## Things to avoid

- Don't edit `dist/` — it is generated by the build.
- Don't commit `.env`, `node_modules/`, or secrets.
- Don't switch package managers (stay on Yarn).
- Don't change `HashRouter` to `BrowserRouter` without accounting for GitHub Pages routing.
